# 目的
DAW（Pro Tools など+ RME等のインターフェース）での音楽制作・ミキシングセッション向けに、LISTENTOのように「ホストが画面映像と高音質ステレオ音声を配信し、リスナーはURLを開くだけでブラウザ上で超低遅延ストリーミングを視聴できるWebアプリケーション」を新規開発してください。

---

# アーキテクチャと通信仕様（厳守）

## 1. サーバーレスP2P WebRTC構成
- 独自バックエンドサーバーは不要とし、フロントエンド（静的HTML/JavaScript）のみで動作させること。
- WebRTCのシグナリングおよびピア接続には「PeerJS（CDN版）」を利用し、無料のパブリッククラウドサーバー（0.peerjs.com）を使用すること。

## 2. 音声コーデックおよびステレオ担保仕様（エラー完全防止設計）
- **コーデック**: Opus（48,000Hz / 2チャンネルステレオ / ビットレート: 320kbps 固定CBR）
- **ブラウザのモノラル化防止パイプライン**:
  - `getUserMedia` で取得した音声をそのままPeerJSに渡さず、必ずブラウザ内部の Web Audio API（AudioContext）を通すこと。
  - `ChannelMergerNode` または `createMediaStreamDestination()` を用い、明示的に `destination.channelCount = 2` を設定したステレオストリームを再生成して送信トラックとすること。
- **安全なSDPトランスフォーム（接続クラッシュの防止）**:
  - 構文エラーを招く正規表現の置換ではなく、SDPの文字列を行単位（`\r\n`）で分解して `a=fmtp` 行に `stereo=1;sprop-stereo=1;maxaveragebitrate=320000;cbr=1` を安全に付与する厳格なヘルパー関数を実装し、ローカル・リモート両方のSDPに適用すること。

## 3. UI・レイアウト要件
- **スクロール保証**: 全体コンテナの `height: 100vh` や `overflow: hidden` による要素の欠損を排除し、画面解像度に関わらず自然に縦スクロール（`overflow-y: auto`）できること。
- **デザイン**: LISTENTOやプロ用DAW機材を想起させる洗練されたモダンダークテーマ（黒・スレートグレー基調、視認性の高いステータスバッジやメーター）。

# 各画面の機能仕様

## 1. 送信者画面 (index.html)

### A. 配信前ステージング＆プレビューエリア
配信を開始する前に、以下の設定と動作テストを自由に行える直感的なUIを用意すること:
1. **オーディオデバイス選択＆ステレオテスト**:
   - ページ読み込み時にマイク権限をリクエストし、利用可能な入力デバイス（RME等）をドロップダウンに列挙。
   - Constraints（echoCancellation: false, noiseSuppression: false, autoGainControl: false, channelCount: { ideal: 2 }, sampleRate: { ideal: 48000 }）を適用。
   - 「音声テスト」ボタンで、左右独立したステレオVUメーター（L/Rレベルインジケーター）がリアルタイムに振れることを視覚的に確認できる。
2. **画面共有選択＆映像プレビュー**:
   - 「画面共有を選択」ボタンでウィンドウや画面（Pro Tools等）を指定し、プレビュービデオに即座に表示。
3. **配信モード選択**:
   - 「映像＋音声」「映像のみ」「音声のみ」をトグルボタンまたはチェックボックスで事前に選択可能。

### B. 配信開始とルーム管理
- ルームID入力欄（デフォルトで重複しにくいランダム文字列を生成）。
- 「配信開始 (Start Streaming)」ボタン:
  - 選択中の映像・音声を合体させた MediaStream でPeerJS待機を開始。
  - 受信側用URL（例: `player.html?room=xxx`）を生成・表示し、「URLをコピー」ボタンを設置。
  - 接続中のリスナー数をリアルタイム表示。
  - リスナーが接続してきたら自動的にストリームを送信（peer.call）する。

### C. 配信中のリアルタイム・無切断切り替え
リスナーとの接続を切断することなく、配信中に以下の操作をシームレスに行えること:
- **音声デバイスの切り替え**: ドロップダウンから別デバイスを選び直すと、`RTCRtpSender.replaceTrack(newTrack)` で送信音声を即座に差し替える。
- **画面共有の切り替え**: 「画面を変更」ボタンで再度画面を選び直し、`replaceTrack` で映像を差し替える。
- **動的ミュート/モード切り替え**:
  - 映像OFF時: `videoTrack.enabled = false` またはCanvasによる軽量な黒画面トラックに差し替え。
  - 音声OFF時: `audioTrack.enabled = false` または無音トラックに差し替え。

## 2. 受信者画面 (player.html)

### A. 接続・再生制御
- URLパラメータ（`?room=xxx`）からルームIDを自動取得。
- ブラウザの自動再生禁止（Autoplay Policy）対策として、画面中央に目立つ「Click to Watch & Listen」ボタンを設置。クリックで再生開始。
- 接続ステータス（Connecting / Live / Disconnected / Error）をバッジで明確に表示。接続エラー時は原因を画面上に分かりやすく表示すること。

### B. プレイヤーUI
- **映像プレイヤー**: アスペクト比を維持したレスポンシブビデオ表示（全画面表示ボタン付き）。
- **音声専用モード時の表示**: ホストが「音声のみ」で配信している場合、映像エリアにはオーディオ波形アニメーションと「Stereo Audio Streaming」のインジケーターを表示。
- **ステレオインジケーター**: 受信側でもL/Rが独立して出力されていることを示すステレオバッジまたは簡易メーターを表示。
- **音量コントロール**: ボリュームスライダー（0〜100%）およびミュートボタン。
- 画面の縦スクロールを妨げないレイアウトにすること。
